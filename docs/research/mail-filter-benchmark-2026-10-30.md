# Mail 邮件自动化筛选效率对照报告（搜索+视图树 vs 滚动遍历 vs OCR）

*测试日期：2026-10-30。设备：iPhone 17（iOS 27.2，LoopCtrl Server 1.98.12）。*  
*测试场景：iOS 邮件（Apple Mail）内筛选并转移 GitHub Actions 运行通知邮件至「垃圾邮件」。*

---

## 一、策略修正背景与测试目的

前期执行中存在策略偏差：将“视图树优先”误解为“停用高层搜索，依靠手工逐屏滚动列表查找”。  
经指令纠偏后，明确正交架构原则：
1. **业务流层（高层功能）**：优先使用 App 内建的「搜索 / 过滤 / 排序」能力缩小候选集，避免无意义的多次全屏滚动；
2. **控制层（原子操作）**：全面采用「视图树优先」原则——通过 `find_element` / `page_source` 定位搜索框、清除按钮、候选建议项、结果单元格及操作工具栏，直接按原生 `ref` 点击；
3. **时序控制**：彻底移除冗余的手动 `sleep`，依托 RPC 返回的 `settle` 动态静止机制驱动流转。

## 二、三阶段执行方式横向能效对比

| 对比维度 | 方式 A：OCR + 坐标 + 手动 Sleep | 方式 B：逐屏滚动 + 纯视图树 Ref | 方式 C：搜索缩小范围 + 视图树 Ref（推荐） |
|---|---|---|---|
| **每封邮件处理总耗时** | 34 – 48 s | 15.3 – 15.9 s | **13.2 – 13.8 s** |
| **全量筛选效率（含定位成本）** | 极低（易漏检历史翻页、OCR 误读） | 中等（逐屏下翻 5–7s/次，网络与遍历累加） | **极高（1 次搜索覆盖全库，毫秒级聚类）** |
| **步骤定位耗时** | `screen_text` 1800–2500ms | `find_element` 700–1100ms | `find_element` **480–700ms** |
| **定位精准度** | 易漂移（坐标受滚动及图层影响） | 100% 节点匹配 | **100% 节点匹配（搜索结果集更纯净）** |
| **漏检风险** | 高（历史邮件无法直观触达） | 高（依赖滚动深度） | **极低（直接索引历史未读与归档）** |

## 三、方式 C（搜索 + 视图树 Ref）详细步骤耗时拆解

搜索流程实测耗时流水（基于 `workflow run` 搜索结果批量移动）：

| 步骤阶段 | 调度方法 | 命中介质 | 实测耗时 | 详细说明 |
|---|---|---|---|---|
| **激活搜索框** | `find_element` + `tap` | 原生视图树 (`ref=el_20`) | 488ms + 3133ms | 自动聚焦搜索框，系统软键盘升起 |
| **键入关键词** | `type` ("workflow run") | 原生按键事件 | 3137ms | 触发系统搜索联想与最佳结果检索 |
| **检索结果抓取** | `page_source` | 视图树全节点 (287 nodes) | 688ms | 瞬时提取出 3 个更深层的历史运行邮件 |
| **循环处理单封 - 选定** | `find_element` (哈希模糊匹配) | 原生视图树 | **481 – 695 ms** | 精准匹配目标 Cell |
| **循环处理单封 - 打开** | `tap{"ref": ref}` | 原生 Ref | **2843 – 3333 ms** | 系统级 Settle 静止确认 |
| **循环处理单封 - 移动** | `find_element` + `tap` | 原生工具栏 Button | **594ms + 2909ms** | 触发 `Toolbar.MoveButton` |
| **循环处理单封 - 垃圾箱**| `find_element` + `tap` | 原生选项 Cell | **531ms + 3202ms** | 优先命中系统建议的「移到“垃圾邮件”」 |
| **循环处理单封 - 回退** | `find_element` + `tap` | 原生 `BackButton` | **1084ms + 1126ms** | 极速回退（非全屏刷新 Settle 仅 400ms） |
| **搜索条件复位** | `find_element` + `tap` | 原生「清除文本」/「关闭」 | 644ms + 2782ms | 清空搜索状态，恢复列表 |

## 四、核心工程结论

1. **分层治理理念**：
   - **业务层**：利用 App 原生的高阶搜索（SearchField）替代机械式滑动遍历，一次搜索即可消除数次耗时 3–5 秒的滚动等待；
   - **驱动层**：拒绝向搜索框或建议项硬编码坐标，搜索框聚焦、建议项命中、结果打开、Toolbar 动作全部由 `find_element` 分配的动态 `ref` 承接。
2. **回退路径性能增益**：
   从单邮件详情页返回搜索结果列表时，界面仅重绘部分列表，底层 `settle` 稳定窗口从全量冷启的 2000ms 大幅缩短至 **400ms**，单封流转时间由 15.8s 压降至 **13.2s**。
